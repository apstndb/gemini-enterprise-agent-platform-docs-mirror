You can use Gemini Omni 1.2 Flash to upscale videos from lower resolutions (360p or 720p) to higher resolutions (720p, 1080p, or 4K) using the Agent Platform API. Standalone video upscaling lets you iterate on prompts at lower resolutions and upscale only the final selected video, either from the preceding turn or from a previously generated video stored in Cloud Storage.

> **Note:** Standalone video upscaling is designed and optimized for videos generated by Gemini Omni models. If you upscale videos that were not generated by Gemini Omni, output quality might vary.

The following models support upscaling videos:

#### Click to expand supported models

- [`gemini-omni-1.2-flash`](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/omni-1-2-flash)

## Supported resolutions and specifications

Standalone video upscaling supports the following resolution transitions and input constraints:

- **360p input video** : Upscale to `720p` or `1080p` . Upscaling directly from `360p` to `4k` in a single request is not supported.
- **720p input video** : Upscale to `1080p` or `4k` . Upscaling from `1080p` to `4k` is not supported.
- **Aspect ratios** : `16:9` (landscape) or `9:16` (portrait).
- **Frame rate** : 24 frames per second (preserved in the output video).
- **Duration** : Up to 15 seconds.
- **Token usage and pricing** : Standalone video upscaling bypasses text reasoning and always incurs zero input tokens ( `total_input_tokens: 0` ). Output video tokens are billed at the same output video token price as all other Omni 1.2 Flash tasks, based on the source and target resolution pair ( `2,896` output video tokens per second for `360p` to `720p` and `720p` to `1080p` , `5,792` output video tokens per second for `360p` to `1080p` , and `11,584` output video tokens per second for `720p` to `4k` ).

## Request requirements

When sending a standalone video upscaling request, make sure your request meets the following requirements:

- **Specify `task: "upscale"`** : You must set `generation_config.video_config.task` to `"upscale"` . If you omit `task: "upscale"` , the API interprets the request as a video editing ( `"edit"` ) operation.
- **Specify a target `resolution`** : You must specify the target `resolution` ( `"720p"` , `"1080p"` , or `"4k"` ) in `response_format` . Omitting the target `resolution` returns an error.
- **Provide a video source** : Provide either an input video in `input` ( `"type": "video"` ) or set `previous_interaction_id` to upscale a video generated in the immediately preceding stateful turn. In multi-turn interactions, only the immediately preceding turn is considered when locating the video to upscale.
- **Optional parameters** : You can specify `generation_config.seed` for reproducible output and attach custom metadata [labels](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/add-labels-to-api-calls) ( `labels` ) to organize requests and track billing costs.

## Upscale videos using Omni 1.2 Flash

To upscale videos using Omni 1.2 Flash, select one of the following interaction modes:

### REST

Video upscaling can take over a minute to complete. You can choose from several interaction modes depending on your workflow:

- **Synchronous: stateless (uploaded video)** : Set `store` to `false` to upscale a 360p or 720p video from Cloud Storage in a single request without persisting interaction state on the server.
- **Synchronous: stateful (previous turn)** : Reference the `previous_interaction_id` from the immediately preceding stateful turn to upscale a previously generated 360p or 720p video.
- **Synchronous: stateful streaming** : Set both `store` and `stream` to `true` to stream the interaction status updates and output video in a single `step.delta` event ( `"type": "video"` ).
- **Asynchronous** : Set `background` to `true` to run video upscaling in the background and retrieve the result later using the interaction ID.

Stored and asynchronous interactions are retained for up to 7 days.

When you configure `"delivery": "uri"` with `gcs_uri` , unary responses return the Cloud Storage URI in `steps[].content[].uri` and streaming responses return it in `delta.uri` . When inline delivery is used ( `"delivery": "inline"` , or when both `"delivery"` and `"gcs_uri"` are omitted), video output is returned as a base64-encoded byte string alongside `"mime_type": "video/mp4"` in `steps[].content[].data` (unary `POST` and `GET` ) or `delta.data` (SSE `step.delta` ). Unlike text or audio deltas, inline video isn't chunked across multiple `step.delta` events—each upscaled video is delivered as a single, complete base64 payload in one `step.delta` event. For large or high-resolution videos, use `"delivery": "uri"` to avoid large HTTP or single-event SSE response payloads.

For more information about using Gemini Omni models with the Interactions API, see [Interactions API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/interactions-api) .

### Synchronous: stateless

Before using any of the request data, make the following replacements:

- `PROJECT_ID` : A string representing your Google Cloud project ID.
- `MODEL_ID` : A string representing the model ID to use. The following is the accepted value:
  - `"gemini-omni-1.2-flash"`
- `CLOUD_STORAGE_VIDEO_URI` : A string representing the Cloud Storage URI that contains the input video (360p or 720p, up to 15 seconds). For example: `"gs://video-bucket/input/video.mp4"` .
- `VIDEO_MIME` : A string representing a video MIME type. The following are accepted values:
  - `video/3gpp`
  - `video/mp4`
  - `video/mpeg`
  - `video/quicktime`
  - `video/webm`
  - `video/x-flv`
  - `video/x-ms-wmv`
- `CLOUD_STORAGE_OUTPUT_URI` : Optional: A string representing the Cloud Storage bucket to store the upscaled video. If not provided, video bytes are returned in the response. For example: `"gs://video-bucket/output/"` .
- `OUTPUT_RESOLUTION` : Required: A string representing the target output resolution. Supported values depend on the input video resolution:
  - For 360p input videos: `"720p"` or `"1080p"`
  - For 720p input videos: `"1080p"` or `"4k"`

HTTP method and URL:

```
POST https://aiplatform.googleapis.com/v1beta1/projects/PROJECT_ID/locations/global/interactions
```

Request JSON body:

```
{
  "model": "MODEL_ID",
  "store": false,
  "input": [
    {
      "type": "video",
      "uri": "CLOUD_STORAGE_VIDEO_URI",
      "mime_type": "VIDEO_MIME"
    }
  ],
  "response_format": [
    {
      "type": "video",
      "delivery": "uri",
      "gcs_uri": "CLOUD_STORAGE_OUTPUT_URI",
      "resolution": "OUTPUT_RESOLUTION"
    }
  ],
  "generation_config": {
    "video_config": {
      "task": "upscale"
    }
  }
}
```

- `CLOUD_STORAGE_VIDEO_URI` : A string representing the Cloud Storage URI that contains the input video (360p or 720p, up to 15 seconds). For example: `"gs://video-bucket/input/video.mp4"` .
- `VIDEO_MIME` : A string representing a video MIME type. The following are accepted values:
  - `video/3gpp`
  - `video/mp4`
  - `video/mpeg`
  - `video/quicktime`
  - `video/webm`
  - `video/x-flv`
  - `video/x-ms-wmv`
- `CLOUD_STORAGE_OUTPUT_URI` : Optional: A string representing the Cloud Storage bucket to store the upscaled video. If not provided, video bytes are returned in the response. For example: `"gs://video-bucket/output/"` .
- `OUTPUT_RESOLUTION` : Required: A string representing the target output resolution. Supported values depend on the input video resolution:
  - For 360p input videos: `"720p"` or `"1080p"`
  - For 720p input videos: `"1080p"` or `"4k"`

HTTP method and URL:

```
POST https://aiplatform.googleapis.com/v1beta1/projects/PROJECT_ID/locations/global/interactions
```
